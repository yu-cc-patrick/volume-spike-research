# 放量信号回测：5 分钟成交量的 10x 事件研究

> 验证一个常见直觉：**5 分钟成交量突然放大 10 倍，是不是可交易的信号？**

## 研究问题

交易者常说"放量必有妖"。但这句话缺少三个关键限定：

1. 相对于什么基准放大？——固定阈值没有意义，必须用滚动均量
2. 放大到什么程度才值得关注？——10x、50x、100x 是不同的现象
3. 放大发生在什么流动性的币上？——僵尸币的 100x 和大盘的 20x 完全不同

本项目先做第一步：**把"放量"定义成可计算的事件，统计它在全市场的分布。**

## 方法

| 项 | 设定 |
|---|---|
| 数据源 | `data.binance.vision` → `futures/um` 5m K 线（本地 `kl/*.zip`） |
| 基准 | 前 **30 天**（8,640 根 5m bar）的滚动均量 |
| 触发条件 | `quote_volume >= 10 × 滚动均量` |
| 事件聚合 | 相邻触发间隔 ≤ 6 根 bar（30 分钟）合并为同一事件 |
| 信号窗口 | 2026-07-03 00:00 — 2026-07-09 23:55 UTC |
| 评估范围 | 币安全部 USDT-M 永续 |

每根 bar 同时计算：

- `ratio` = 当前 5m quote_volume / 基准均量
- `peak_ratio` = 一个事件内的最大放大倍数
- `baseline_qv_usdt` = 事件发生前的平均每 5 分钟成交额（流动性代理）

## 结果

| 指标 | 数值 |
|---|---|
| 触发事件总数 | **2,012** |
| 通过流动性质量筛选 | **168** |
| 最大单事件峰值 | **729.5x**（ARPA） |

产出两个文件：

- `events.csv`：全部 2,012 个事件，按峰值倍数降序
- `quality_events.csv`：168 个通过流动性门槛的事件（剔除僵尸币/微型盘的噪声）

### CSV 字段

```
symbol, peak_time_utc, peak_ratio, peak_qv_usdt,
baseline_qv_usdt_5m, n_bars, start_utc, end_utc
```

- `peak_ratio`：事件内最大放大倍数
- `baseline_qv_usdt_5m`：基准流动性，用来分层
- `n_bars`：事件持续多少根 5m bar

## 复现

```bash
# 1. 下载 binance.vision 的 futures/um 5m 数据到 kl/
# 2. 运行
python3 analyze.py
```

脚本会输出按流动性分层、按倍数分档的事件统计，并重写 `events.csv`。

## 局限

这是一个**事件检测**研究，不是完整策略回测。它回答"放量事件长什么样、在哪里发生"，**不回答"事件后能不能赚钱"**：

- 未统计事件后的前瞻收益（1h / 4h / 24h）
- 未考虑手续费、滑点、资金费率
- 单一时间窗口（7 天），未做跨周期稳健性检验
- 数据依赖本地 zip，仓库不含行情文件

下一步是把 `events.csv` 接到价格数据上，做前瞻收益分布和分组统计。
